# 법령 대조 개편 계획 — 코드가 규칙, Jev가 판정, LLM이 생성

작성 2026-09-26. 목적: 앱의 문제·해설·수치가 **현행 법령 원문과 일치**하도록 확실하게 관리한다.
지금까지 "확인했다"는 결과가 세 번 어긋난 원인: `tools/check_law.py` 는 숫자가 인용 조문 안에 "어딘가 있는지"만 봐서
(예: 조문에 10%·15%가 둘 다 있으면 15%를 잘못 써도 통과) 오늘 "133개 대조, 차이 0건"이 나왔지만 실제로는 틀린 곳이 있다.

## 역할 분담 (Jev + LLM 가이드의 원칙: 정해진 규칙은 코드, 좁은 판정은 Jev, 자유 생성은 LLM, 최종 권한은 코드·사람)

| 단계 | 담당 | 내용 |
|---|---|---|
| 1. 문항 ↔ 근거 조문 연결 | LLM | 모든 문항에 법령·조·항 연결 → `data/law-refs.js` |
| 2. 조문 원문 저장 | 코드 | 법제처 API로 받은 조문 원문을 `data/law-snap.json` 에 저장 |
| 3. 개정 감지 | 코드 | 저장 원문 vs 현행 원문 **글자 단위 비교**. 바뀐 조문에 걸린 문항만 목록화 (AI 판단 없음, 한 글자라도 바뀌면 반드시 걸림) |
| 4. 일치 판정 | **Jev** | "앱 문장이 이 조문과 맞나?" → 확률(noul). 판정마다 질문·근거·확률 기록 |
| 5. 라우팅 | 코드 | 확률 ≥ 기준 → 통과 / 애매 → 사람 검토 / 불일치 → 수정 후보 |
| 6. 수정 문구 작성 | LLM | 불일치 문항의 수정안 + 원문 링크 |
| 7. 반영 | 사람 | PR에서 원문 링크 확인 후 Merge |

## 할 일 (순서대로)

1. **Jev 시험**: `python tools/jev-test.py`. 요청 형식(`state` + `questions.{name}.type='noul'`)은 블로그 기준 추정이라 오류가 나면 TypeSafe 공식 문서(console.typesafe.ai → Documentation)로 형식을 고친다. 14개 중 Claude 판정과 몇 개 같은지 확인.
   - 특히 숫자·기준일 차이(S-SR12 검사완료일 vs 청구일, S-S34 30% vs 계약보증금상당액)를 잡는지가 핵심.
   - 결과가 나쁘면 질문 문구를 좁혀 다시(예: "app 의 지급 기한 기산일이 clause 와 같은가?"). 그래도 안 되면 Jev는 1차 필터로만 쓰고 판정은 사람.
2. **조문 비교 스크립트** `tools/clause-check.mjs` 작성
   - `data/law-refs.js` 의 (법령, 조) 목록 → 법제처 API로 현행 조문 받기(`check_law.py` 의 articles() 방식과 동일: law는 lawService MST, admrul은 ID)
   - 비교 텍스트는 조문 내용만(항·호·목 내용). `조문시행일자`·`조문변경여부` 같은 메타데이터는 빼야 타법개정 때 헛경보가 안 남
   - `--init`: `data/law-snap.json` 에 없는 조문을 채움 / 기본: 달라진 조문과 거기 걸린 문항 ID 출력, 차이 있으면 종료코드 1
   - 네트워크 없이 시험할 수 있게 `--fixture <폴더>` 옵션: 일부러 한 글자 바꾼 조문을 넣었을 때 잡는지 확인
3. `tools/check_law.py` 가 `data/law-refs.js` 의 조문도 인용으로 읽게 해서 '근거 없음 54개'를 없앤다(ALIAS 에 없는 이름은 추가)
4. 나머지 문항 전체(필기 401 · 실기 200 + index.html · steps.js · tabs.js · game.html · journey.js)도 1번처럼 조·항 연결 → Jev 판정 → 기록
5. 틀린 곳 수정: **브랜치 따로**, 한 줄에 한 항목 형식 유지, 필기는 answer 인덱스와 해설 일치 확인, `node tools/check-data.mjs` 통과. PR 본문에 파일:줄 | 전 | 후 | 근거 조문 | 법제처 원문 링크. constraints.md 에 금지 정규식 추가(옛 값 재유입 방지)
6. 월요일 루틴(`tools/law-check-routine.md`)에 clause-check 단계를 추가
7. 기준값(`data/law-baseline.json`)에 앱이 쓰는데 빠진 규정 추가 검토: 조달청 시설공사 적격심사세부기준(2026.7.1), 지방자치단체 입찰 및 계약 집행기준(2026.7.1), 조달청 일반용역 적격심사 세부기준(2026.7.27), 조달청 물품구매적격심사 세부기준(2026.5.26)
